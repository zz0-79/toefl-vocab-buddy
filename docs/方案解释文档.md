**服务对象**：高一学生「渴望进步的小李」  
**提交人**：____________　**日期**：2026年5月29日

## 一、问题背景与客户画像

小李在求助信中暴露出四个相互叠加的困境：

| 表层现象 | 深层痛点 |
|----------|----------|
| 词汇量少，阅读理解头疼 | **能力焦虑**：将「词少」等同于「考不好」，形成习得性无助 |
| 背字典第二天全忘 | **方法错位**：用「海量输入」代替「可检索的长时记忆」，缺少间隔与情境 |
| 不知道从哪里补救 | **路径缺失**：没有可执行的「第一步」，目标过大导致瘫痪 |
| 明日复明日、缺乏行动 | **动机结构断裂**：只有远期压力（TOEFL），没有近期可感知的正向反馈 |

**核心结论**：小李需要的不是「更狠的背词计划」，而是 **低门槛启动 + 即时正向反馈 + 可累积的可见进步**。

---

## 二、前人经验对比（为何常见做法不够用）

我们调研并对比了四类常见做法：

| 方案类型 | 代表做法 | 优点 | 对小李的局限 |
|----------|----------|------|----------------|
| 纸质字典 / 单词书 | 按字母背、抄释义 | 系统、权威 | 无发音情境、无复习提醒；**第二天全忘**正是因为缺少提取练习与反馈 |
| 商业背单词 App | 百词斩、墨墨、不背单词 | 打卡、词书、游戏化 | 功能重、社交与付费干扰多；小李已 **挫败**，需要的是「今天只完成 3 个词也算赢」而非再签一个宏大计划 |
| 间隔重复工具 | Anki | 科学、可定制 | 制卡成本高、上手曲线陡；高一课业忙，**等不到「学会 Anki」才开始背词** |
| 纯意志力 / 明日计划 | 「明天背 50 个」 | 零成本 | 无外部记忆、无即时奖励；正是小李描述的 **明日复明日** |

**借鉴点（吸收，不照搬）**：

- 从 **间隔重复（艾宾浩斯）**：强调「24 小时内、第一周内复习」→ 本产品的 **到期复习队列 + 1/3/7/14 天间隔**  
- 从 **游戏化 App（多邻国等）**：强调「打卡、连胜、想赢」→ **每日打卡、XP 等级、徽章、词汇闯关**  
- 从 **词典工具**：强调「音标 + 发音 + 例句」→ 接入 Free Dictionary API，而非静态死释义  

**差异化定位**：不做「又一个背单词 App」，而是 **科学复习 + 游戏激励 + 心理正向循环** 的轻量 Web 教练。

## 二（补）. 团队建议融入说明

根据课程讨论，我们将三条建议 **落地为具体功能**：

### 建议 1：对抗遗忘（艾宾浩斯曲线）

| 理论要点 | 产品实现 |
|----------|----------|
| 遗忘高峰在 **24 小时内** 与 **第一周** | 掌握新词后，自动安排 **第 1 天复习**；阶段间隔 **1→3→7→14→30 天** |
| 第 1 天学新词，第 2 天复习前一天 | 「今日待复习」列表 +「复习模式」按钮（记住了 / 忘了） |
| 每 7～10 天总复习 | **每周词汇小测验**（5 题选择题，≥5 词且满 7 天触发） |

### 建议 2：游戏化（Gamification）

| 理论要点 | 产品实现 |
|----------|----------|
| 小游戏 / 竞赛 | **词汇闯关**：看单词选释义，连对得分，答错结束 |
| 打卡机制（多邻国） | **今日打卡**按钮 + **连续天数 🔥** + 打卡 +5 XP |
| 学生想「赢」 | **XP / 等级**、**徽章墙**（连续 3 天、周测及格等） |

### 建议 3：心理层面

| 理论要点 | 产品实现 |
|----------|----------|
| 用对方法→背得住→成就感→更愿意背 | 首页 **正向循环图** + 动态文案反馈 |
| 死记硬背→记不住→不想背 | 用 **间隔复习** 替代「抄字典」；鼓励语强调「遗忘正常，复习即对抗」 |
| 需要正向反馈 | 掌握 +10 XP、复习 +15 XP、进度条、升级动画 |

## 三、三个备选方案与最终选择

### 方案 A：纯词表 + 自测题库（静态 HTML）

- **思路**：内置 TOEFL 词表，点击显示中文，自测对错。  
- **优点**：开发快、无网络依赖。  
- **缺点**：无真实发音、无动态鼓励；**不满足「API 接入」**；难以解决「不知道从哪开始」的情绪问题。  
- **结论**：❌ 不选——技术考核不达标，且痛点覆盖不全。

### 方案 B：接入 ChatGPT / 大模型生成例句与计划

- **思路**：用 AI 每日生成背词计划、造句。  
- **优点**：个性化强、对话感好。  
- **缺点**：需 API Key、费用与审核；部署到 GitHub Pages 易泄露密钥；高一用户 **网络与账号门槛高**。  
- **结论**：❌ 不选——落地与作业公开部署风险大，维护成本高。

### 方案 C：词途（本方案）—— 词典 API + 微习惯 API + LocalStorage + 轻交互

- **思路**：  
  1. 用 **词典 API** 提供权威释义与发音（解决「背了不会用、不会读」）；  
  2. 用 **Advice Slip / 治愈图 API** 提供随机微行动与情绪调节（解决「启动困难、挫败」）；  
  3. 用 **LocalStorage** 记住掌握词、收藏、心情、连续天数（解决「第二天像没学过」的遗忘感）；  
  4. 默认 **每日 3 词** 小目标（解决「明日复明日」）。  
- **优点**：满足全部硬性技术指标；无需后端与密钥；可静态托管；与小李叙事高度贴合。  
- **缺点**：词库为精选 TOEFL 高频词而非官方全集；需联网拉取 API。  
- **结论**：✅ **最终选择**——在创意、技术、可演示性之间平衡最佳。

**选择理由（一句话）**：在作业约束下，方案 C 唯一能同时满足 **公开部署、API、记忆、交互**，且直接对准小李的 **拖延 + 缺反馈 + 方法迷茫** 三角痛点。

## 四、产品设计说明（如何服务小李）

### 4.1 功能架构（v2）

```
┌─────────────────────────────────────────────────────────┐
│  心理层：正向循环图 · 心情打卡 · 反「死记硬背」文案        │
├─────────────────────────────────────────────────────────┤
│  科学层：艾宾浩斯复习队列(1/3/7/14天) · 每7天周测          │
├─────────────────────────────────────────────────────────┤
│  游戏层：打卡 · XP/等级 · 徽章 · 词汇闯关小游戏            │
├─────────────────────────────────────────────────────────┤
│  学习层：TOEFL词库 → 词典API → 新词掌握 / 到期复习         │
├─────────────────────────────────────────────────────────┤
│  支持层：微习惯API · 治愈图API · 拖拽排序                  │
├─────────────────────────────────────────────────────────┤
│  记忆层：LocalStorage v2（wordSRS、打卡、XP、测验记录）    │
└─────────────────────────────────────────────────────────┘
```

### 4.2 UI 风格与客户匹配

| 设计决策 | 理由 |
|----------|------|
| 深色界面 + 蓝绿强调色 | 减少长时间背词的眼疲劳；偏「专注工具」而非儿童向花哨 |
| 中文界面 + 英文词条 | 符合高一用户阅读习惯，降低理解成本 |
| 首屏可见「今日 0/3」 | 把抽象「要背单词」变成具体数字，对应小目标疗法 |
| 大按钮：换一个词 / 标记已掌握 | 减少决策步骤，对抗拖延 |
| 侧边「微习惯」「减压图」 | 承认焦虑与疲惫，而非只施压 |

### 4.3 典型使用路径（小李的一天）

1. 打开网页 → **今日打卡** → 选心情  
2. 查看 **今日待复习**（昨天学的词）→ 进入复习模式 →「记住了」  
3. 学新词：点「学新词」→ API 释义 + 发音 →「标记已掌握」（自动排入艾宾浩斯计划）  
4. 完成每日新词目标 → 进度条满 → 获得 XP / 可能升级  
5. 玩一局 **词汇闯关** 或满 7 天做 **周测**  
6. **次日再开**：复习队列、打卡 streak、XP 均从 LocalStorage 恢复  

**进阶节奏（可调每日目标至 30）**：第 1 天 30 新词 → 第 2 天 30 新词 + 复习昨日 → 第 7 天周测。

## 五、技术实现说明（对应技术 40 分）

### 5.1 外部 API（实时动态数据）

| API | 用途 | 请求示例 | 页面表现 |
|-----|------|----------|----------|
| Free Dictionary API | 释义、音标、发音 MP3 | `GET https://api.dictionaryapi.dev/api/v2/entries/en/{word}` | 单词卡片、🔊 播放 |
| Advice Slip API | 微习惯随机建议 | `GET https://api.adviceslip.com/advice` | 「微习惯挑战」引用框 |
| Dog CEO API | 减压随机图片 | `GET https://dog.ceo/api/breeds/image/random` | 「减压一刻」图片区 |

**异常处理**：网络失败时显示友好提示；Advice 失败时使用本地兜底文案。

### 5.2 LocalStorage（赋予记忆）

- **存储键**：`toefl_vocab_buddy_v2`（自动从 v1 迁移）  
- **存储内容**：`wordSRS`（艾宾浩斯日程）、`mastered`、`xp`、`badges`、`checkedInToday`、`lastQuizDate`、`definitionsCache` 等  
- **验证方法**：标记 1 个词已掌握 → 刷新页面 → 列表与今日计数仍在；换日期逻辑见 `app.js` 中 `resetTodayIfNeeded()`  

### 5.3 交互元素（≥3，且可演示）

| # | 交互 | 实现要点 |
|---|------|----------|
| 1 | 今日打卡 | Duolingo 式打卡 + streak |
| 2 | 艾宾浩斯复习 | 到期词列表 + 记住了/忘了 |
| 3 | 标记已掌握 | 写入 SRS + 新词计数 + XP |
| 4 | 周测 / 词汇闯关 | 游戏化测验 |
| 5 | 心情打卡 | 个性化鼓励 |
| 6 | 收藏 / 发音 / 学新词 | 核心学习流 |
| 7 | 每日目标 1～30 | 适配「每天 30 词」节奏 |
| 8 | API 建议 / 治愈图 | 外部数据 |
| 9 | 拖拽排序 / 清空 | 列表管理 |

### 5.4 文件与部署

| 文件 | 职责 |
|------|------|
| `index.html` | 结构、语义化区块 |
| `styles.css` | 响应式布局与视觉 |
| `app.js` | 业务逻辑、API、存储 |

**部署**：GitHub Pages 静态托管，无需服务器。

## 七、总结

「词途」将小李的困境拆解为 **情绪 → 行动 → 学习 → 记忆** 四层，用三个备选方案对比后选定 **轻量 Web + 多 API + 本地记忆** 路线，在满足课程技术指标的同时，真正对准 **拖延、挫败、无反馈** 的深层痛点，而非仅堆砌背单词功能。
