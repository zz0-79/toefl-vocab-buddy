## 一、问题背景：小李真正难在哪里

小李在求助信里写到的，不只是「词汇量少」这一件事。表面上看，他读阅读理解头疼、背字典第二天就忘、不知道从哪里补救、明明知道要背单词却总是拖到明天。往深处看，这些现象背后叠着四层困境。

第一层是能力焦虑。他把「词少」直接等同于「考不好」，久而久之容易产生「反正学不会」的无力感。第二层是方法错位。他用背字典、抄释义的方式往脑子里灌词，缺少在真实语境里「想起来」的练习，也缺少在关键时间点把词拉回来的复习，所以会出现「背了像没背」的体验。第三层是路径缺失。一想起 TOEFL，脑子里跳出来的往往是「要背几千个词」这种巨大目标，大到不知道第一步该迈哪一只脚，于是干脆不动。第四层是动机断裂。考试压力是远期的，而每天坚持背词带来的回报是模糊、延迟的，没有马上能感觉到的进步，就很难对抗「明日复明日」。

因此，我们的核心判断是：小李需要的不是更狠、更多的背词计划，而是一套「容易开始、马上有反馈、进步看得见」的机制。产品「词途」就是按这个方向设计的。

## 二、前人经验：常见做法为什么帮不到他

在设计之前，我们对比了四类常见做法，看看它们好在哪里、又为什么解决不了小李的具体处境。

纸质字典和单词书系统、权威，但几乎没有发音和情境，也不会提醒你在什么时候复习。小李「第二天全忘」，往往不是因为不努力，而是因为学完之后没有按遗忘规律去提取、去巩固。百词斩、墨墨、不背单词等商业 App 有打卡和游戏化，功能也很全，但对一个已经感到挫败的学生来说，界面里的社交、词书、付费和复杂设置，有时反而加重压力。他更需要的是「今天只认真学完 3 个词也算赢」，而不是再签一份看起来很宏大的计划。Anki 等间隔重复工具非常科学，但制卡、调参都要时间，高一课业已经很满，很多人「还没学会 Anki，就已经放弃背词了」。至于靠意志力硬扛、口头说「明天背五十个」，成本虽低，却没有外部记忆、没有即时奖励，正是小李自己描述的「明日复明日」。

我们并不是否定这些方法，而是有选择地吸收：从艾宾浩斯曲线里吸收「24 小时内、第一周内要复习」的节奏，做成到期复习队列和 1、3、7、14、30 天的复习间隔；从多邻国等产品里吸收打卡、连胜、想赢的感觉，做成每日打卡、经验值、等级和徽章；从词典工具里吸收音标、发音和例句，通过词典 API 实时拉取，而不是页面上写死的死释义。词途的定位因此很清楚：它不做「又一个功能堆满的背单词 App」，而是一个把科学复习、游戏激励和心理正向循环装在一起的轻量网页教练。

## 三、课程讨论中的三条建议如何落地

### 对抗遗忘：艾宾浩斯曲线

心理学上的艾宾浩斯遗忘曲线告诉我们，遗忘速度最快的时间段，通常在学完之后 24 小时内，以及第一周内。如果只靠一次「背过」，而不在高峰来临前复习，记忆就会大量流失。比较合理的学习节奏是：第一天学一批新词，第二天在学新词的同时复习前一天的内容，每隔大约一周到十天再做一次总复习或小测验。

词途里，每当用户把一个词标记为「已掌握」，系统会自动为它排上复习日程：第一次复习在 1 天后，之后依次是 3 天、7 天、14 天、30 天，形成阶梯式巩固。页面上有「今日待复习」列表，提醒哪些词已经到期；进入复习模式后，用户可以选择「记住了」或「忘了」——记住则进入下一阶段并获得经验值，忘了则缩短间隔、明天再练，传达「遗忘是正常的，复习就是在对抗遗忘」的观念。此外，当已学词汇达到一定数量且距离上次测验已满约 7 天时，会开放「每周词汇小测验」，用五道选择题做阶段性检验，对应「每 7～10 天总复习」的建议。

### 游戏化：让学生愿意开始、愿意坚持

单纯讲道理很难对抗拖延，游戏化是把「坚持」变得有点好玩、有点想赢。词途设计了类似多邻国的「今日打卡」和连续天数显示，打卡成功会积累经验值。掌握一个新词、完成一次复习、在周测里答对，都会获得不同数量的 XP，累积后可以升级，并解锁徽章，例如「连续 3 天」「周测及格」等。另外还有「词汇闯关」小游戏：看英文单词，从四个释义里选对，连对可以一直玩，答错则本局结束并显示得分，利用学生「想赢一把」的心理，把复习藏在游戏里。每日新词目标可以在 1 到 30 之间调节：小李刚开始可以设 3 个，降低启动难度；熟练以后再逐步提高，对应「第一天 30 个新词、第二天 30 个新词加复习昨天」的进阶节奏。

### 心理层面：打破「记不住 → 不想背」的死循环

死记硬背容易陷入恶性循环：方法不对 → 记不住 → 更不想背 → 更焦虑。反过来，如果用对方法、真的记住了、马上得到正向反馈，就更容易愿意继续。词途首页用「用对方法 → 背得住 → 有成就感 → 更愿意背」这条链做可视化提示，并根据用户当天是学了新词、完成了复习，还是还有待复习的到期词，动态更新文案。心情打卡则根据「很好」「还行」「疲惫」「焦虑」给出不同强度的鼓励，承认情绪而不是只施压。进度条、经验值、升级动画，都是把「我今天其实有进步」这件事变得具体可见，用来补上小李最缺的「正向反馈」。

## 四、三个备选方案与为什么选「词途」

我们曾经考虑过三种技术路线。

方案 A 是用纯静态词表加自测：开发快、不依赖网络，但没有真实发音，也没有从互联网拉取数据的 API，不满足作业对「外部 API」的要求，也解决不了情绪和启动难的问题，因此放弃。

方案 B 是接入 ChatGPT 等大模型，每天生成背词计划和例句，个性化很强，但需要 API 密钥，部署到 GitHub Pages 这类公开页面又有泄露风险，对高一学生来说账号和网络门槛也偏高，维护和成本都不划算，因此放弃。

方案 C 就是现在的「词途」：用 Free Dictionary API 获取释义、音标和发音；用 Advice Slip API 获取随机的微习惯建议；用 Dog CEO API 获取减压图片；用浏览器 LocalStorage 保存掌握词、复习计划、打卡、经验值和测验记录；默认每天 3 个新词的小目标，降低「明日复明日」的概率。它满足公开部署、API 接入、本地记忆和多项交互的作业要求，又直接对准小李的拖延、挫败和方法迷茫，所以在创意、技术和可演示性之间，我们最终选择了方案 C。

## 五、产品如何陪伴小李度过一天

小李打开词途，可以先点「今日打卡」，点亮连续学习天数，再选一下今天的心情，看到一句适合自己的话。如果昨天学过词，「今日待复习」里会出现到期的词，他应优先复习这些——因为这正是遗忘曲线最高的时段。复习时看释义、听发音，记得住就点「记住了」，记不住就点「忘了，明天再复习」，不必自责。

复习之后进入新词学习：点击「学新词」，系统从 TOEFL 高频词库里抽一个词，向词典 API 请求英文释义和读音。他读一读、听一听，觉得会了就可以「标记已掌握」，这个词会自动进入艾宾浩斯计划，同时今日新词计数加一，经验值增加。难词可以收藏，之后在词库里拖拽调整复习顺序。完成每日目标后，进度条会满，页面会鼓励他「比昨天更进一步」。学累了可以拉一条微习惯建议，或换一张随机治愈图；想玩的话可以开一局词汇闯关，或者到了第七天做一次周测。关掉浏览器后，第二天再打开，复习队列、打卡天数、经验值和词库都还在，因为数据写在 LocalStorage 里，除非他主动清空。

界面采用深色背景和蓝绿色强调，减轻长时间盯屏的疲劳；中文说明配英文词条，符合高一用户的阅读习惯；首屏就能看到「今日新词 0/3」这类具体数字，把模糊的「要多背单词」变成可完成的小任务。大按钮、少步骤，是为了减少「想半天要不要开始」的拖延。

## 六、技术实现简述

本网站是静态页面，可部署在 GitHub Pages，不需要自己的服务器。三个外部 API 分别承担不同职责：Free Dictionary API 根据单词返回释义、音标和发音地址，用于单词卡片和播放按钮；Advice Slip API 返回一条英文人生建议，我们加上「微习惯」前缀，用作降低行动门槛的提示；Dog CEO API 返回随机小狗图片 URL，用于「减压一刻」。若网络请求失败，页面会显示友好提示或本地备用文案，避免白屏。

用户的所有学习记录在浏览器 LocalStorage 中，键名为 `toefl_vocab_buddy_v2`，内容包括艾宾浩斯日程（wordSRS）、已掌握词、收藏、每日目标、今日新词数、今日复习数、连续天数、是否已打卡、心情、经验值、徽章、上次周测日期、释义缓存等。关闭页面再打开，或第二天再来，数据都会保留。交互上除了心情、打卡、掌握、收藏、发音、调节每日目标、拉取 API 内容、拖拽排序、清空记录之外，还有专门的复习模式、周测和词汇闯关，远远超过作业要求的「至少三种交互」。

源代码分为三个文件：`index.html` 负责页面结构，`styles.css` 负责样式与布局，`app.js` 负责业务逻辑、API 调用和数据读写。提交前建议联网实测：换词能否出释义、发音能否播放、建议和治愈图能否加载、掌握一词后刷新是否仍在、控制台是否有报错。

## 七、总结

「词途」从高一学生小李的真实困境出发，把问题理解为方法、节奏、反馈和情绪而不只是「词不够多」。我们对比了字典、商业 App、Anki 和靠意志力硬扛等前人经验，在三个备选技术方案中选择了词典与减压 API 加本地记忆的轻量网页路线，并把艾宾浩斯复习、游戏化打卡闯关、心理正向循环三条团队建议，落实为具体可见的功能。它既完成课程对 API、LocalStorage 和交互的技术要求，也试图回答小李信里那句话：我不知道从哪里开始——从这里，每天一点点，并且看得见自己的进步。
